## 0. 项目形态与叙事 (v0.4 定稿口径)

- **独立项目** `dc-twin` (新 repo), 通过组合契约使用仓库内核;
  desktop-agv-demo 打包为可安装库 `agv-warehouse-core` (见 §8)。

    互不覆盖 (差异矩阵见 §7.2)。
  - 依赖口径: "不依赖任何 NVIDIA 运行时/许可工件; 仅借鉴公开架构范式"
    (替换"零 NVIDIA 依赖/复刻"字样——"复刻"自贬新颖性且引法律误读)。
  - 专利段只做事实分层 (公开出处 + 本项目差异点), 不做法律结论。

## 2. 场景拓扑

```
   ┌─ 卡车位 tk:I1-I3 (入库) ─┐                      ┌─ 卡车位 tk:O1-O3 (出库) ─┐
卡车→│ D_G 交付台延伸段        │→ stand 交接台 → 128 架存储矩阵 → stand → 交付台 →│ 装车 │→卡车
   └────────────────────────┘                      └──────────────────────────┘
```

- **truck bay 复用交付台**: 16 个 D_G 交付台已存在于北缘 (dock_y =
  matrix_h/2 + berth_depth_y/2), 卡车泊入 dock_y 外侧 (`berth_depth_y`
  参数直接复用); 新节点类 `tk:*` 进图, **装车腿复用 trunk 腿类型**
  (避免 dispatcher 新增腿类型); floor ±3.2m 有余量, 需避
  x∈(-2.22,-1.10) 盲走走廊 (warehouse_cell.py:68)。
- truck agent 双态抽象 (为运输车队预留, §8.4): `BerthTruck` (P0 静体,
  mocap+货箱 geom, 机制已有) / `RoadTruck` (预留)。
- 装卸证据事件四态: 装车/在途/到货/卸车 各态独立证据类型;
  出库账本闭合延伸到"托盘上车"。

## 3. 分期与验收 (v0.4: 全部改为可测判据)

### P0 月台+卡车闭环 (1-2 天)
- 内容: tk:* 节点 + BerthTruck + 到达时刻表 (DemandEngine 扩展) +
  装车证据事件 + 账本出库闭合。
- **验收 (可测)**: 复用 scripts/press.py 基建跑 30min;
  (a) 仿真时钟口径钉死 (sim_t 判据, 非 wall); (b) ≥1 辆卡车完成
  装车离场且**账实三元等式成立**: 账本托盘集合 = truth 物理集合
  (evaluator 断言); (c) 全库 pytest 维持全绿。
- 隐藏工作量 (自审#1/#2 确认): 账本 (truck 维度)/调度 (tk 目标)/
  需求引擎 (到达时刻表) 三处扩展是"90% 复用"叙述外的大头。

### P1 虚拟摄像头 + 感知融合层 (2-3 天)
- 内容: 月台+关键巷道 ROI 摄像头 → 检测事件 (schema 对齐 Blueprint
  2D 检测事件: id/type/confidence/ts/source) → 融合层 → 门控。
- **分工边界 (high 风险缓解)**: LiDAR 观测通道 = 避障决策侧 (既有);
  摄像头事件 = 证据门控侧 (新增)。融合层复用 mj_ray 同源感知实现,
  **禁止读真值**; 与 observation.py 双通道消费者互不越界。
- 噪声参数: 无公开标定源 → 定位为 **SDG 合成参数 + 敏感性扫描**
  (漏检 0-30% × 误检 0-10% 网格)。
- **验收 (正向断言, 修"不升"空洞)**: 基线 unsafe=0 使"不升"不可测;
  改为: 注入漏检 20% + 误检 5% 时, (a) unsafe 提交率仍 = 0;
  (b) false reject 率 ≤ 5%; (c) 吞吐损失 ≤ 10%; 真值隔离审计
  扩展覆盖融合层后 PASS。

### P2 What-if 优化器 + KPI 曲面 (1-2 天)
- 内容: 场景矩阵 (车队 6/8/10 × 月台 4/6 × 到达 1/2/3) × 30 seed;
  对齐 NVIDIA Profile 惯例增加 **KPI & Metrics / Latency 章节**
  (吞吐/利用率/账实一致率/门控时延分位数)。
- **验收**: 先跑 3×3×1 摸底测计算量 (自审#2: 810 runs 需先摸底),
  再全矩阵; 产出曲面报告。
- AI-Agent 样例 (对标 Safety Inspector): "证据审计 agent" 消费事件
  ring, 对账实分歧发告警。

### P3 照片级演示片 (1 天)
- 真值 CSV → Blender 管线; DC 全景 + 证据门控特写 (故障对照片手法)。
- 验收: 60-90s 成片。

## 7. NVIDIA 对标 (v0.2 调研 + 自审#3 修正)

### 7.1 对标架构
Warehouse Blueprint (VSS 3.0) 分层: Foundational Microservices
(Warehouse 2D/3D + VIOS) → Blueprints → AI Agents (Safety Inspector
等) → Agentic Application; SDG 支线 (Replicator, PhysicalAI-SmartSpaces
数据集); 用例: 资产追踪/安全近距/过程优化。他们是**感知平台** (视频→
实时分析+3D 校准), 仿真/DT 仅是 SDG 支撑环节。

### 7.2 差异矩阵 (不做"对等替代"声明)

| 维度 | NVIDIA Blueprint | 本项目 |
|---|---|---|
| 感知 | 真实视频 MTMC 管线 | 合成检测事件 (传感器模型) |
| 物理 | 无闭环 (SDG 用) | MuJoCo 1kHz × 调度 × 故障闭环 |
| 执行可信 | 消息 ACK/告警 | **证据门控事务+恢复对账** |
| 底座 | USD/专有 (EULA) | 纯开源 pip 栈 |

### 7.3 专利地形 (事实分层, 无法律结论)
US12084280 (物流流控制) / US12314060 (DT+ML 规划) / **US12585282B2
(DT+人类反馈训库存机器人)** / US11767167 (料箱检测) —— 通用 DT 仓储
已被占位; 本项目可主张点收敛于**执行证据协议** (判据时序窗/传感器
仲裁与账本原子提交耦合/故障恢复对账), 需 FTO 检索。
