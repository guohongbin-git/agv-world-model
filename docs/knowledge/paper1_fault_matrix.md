# Paper I 故障注入实验矩阵 V0.1（GPT 评审通道定稿）

来源：ChatGPT 评审会话 2026-10-12。22 场景 + 六不变量 + 审计 schema + 消融设计。
用途：`tests/` 参数化测试 + 论文实验配置的第一版。

## 核心工程原则

> 数据库可以回滚，物理世界不能回滚；系统必须能够识别、隔离和恢复这种不对称性。

## G1 状态机（修正版）

```
PREPARED            持久化任务意图、资源预约和命令 ID（必须在不可逆物理影响前）
  → PHYSICAL_EXECUTING   机器人执行，收集物理证据
  → EVIDENCE_VERIFIED    形成不可变 EvidenceVerdict
  → commit_transfer()    版本检查、写状态、事件、幂等凭证，同一事务
  → COMMITTED            物理证据与业务状态闭合
  → RECONCILIATION_REQUIRED  结果不确定，隔离并复核
```

三个独立标识不得混用：`command_id`（跨重试幂等）、`evidence_id`（证据引用）、
`run_id`（运行级审计）。恢复机制在重启时发现未闭合任务，通过重新观测现场
判定真实状态，不依赖故障瞬间的异常状态写入。

## A. 感知与证据故障（6 项）

| ID | 注入条件 | 期望结果 |
|---|---|---|
| S01 | 货叉没接触托盘但高度信号显示已抬起 | 拒绝取货提交；状态不变 |
| S02 | 托盘稳定承托但 LiDAR 连续丢束 | 不把扫描缺失当不存在；维持安全状态，允许恢复观测 |
| S03 | LiDAR 虚假障碍回波 | 可保守停车，但不得写成经物理证实的障碍事件 |
| S04 | 遮挡致障碍未检出且接近碰撞区 | 测量危险接近和碰撞；不能凭错误观测宣告路径安全 |
| S05 | 重放旧 EvidenceVerdict 超过有效窗 | 拒绝提交，报告证据过期 |
| S06 | 用托盘 A 的证据提交托盘 B 的转移 | 身份与命令绑定校验失败，拒绝 |

## B. SQLite 事务与持久化故障（8 项）

| ID | 注入位置 | 期望结果 |
|---|---|---|
| D01 | PREPARED 持久化前写入失败 | 不执行物理动作，不产生业务变化 |
| D02 | PREPARED 成功后物理动作前进程退出 | 重启识别未闭合命令；确认未执行后安全取消/恢复 |
| D03 | 物理动作完成、BEGIN 前进程退出 | 重启后隔离资源并现场对账 |
| D04 | 事务中托盘位置更新后异常 | 所有业务修改回滚 |
| D05 | 事务中事件插入后 COMMIT 前异常 | 状态和事件全部回滚 |
| D06 | COMMIT 成功但调用方未收到 ACK | 重试返回原结果，不生成重复事件 |
| D07 | SQLITE_BUSY / 锁超时 | 有界重试或安全失败，不重复提交 |
| D08 | 磁盘满 / I/O 错误 | 禁止假成功；重启后检测未闭合任务并对账 |

D04-D06 必须支持指定程序位置注入（非仅关闭数据库）。D06 是"提交结果
不确定"典型：用超时判失败再执行物理动作会造成严重错误。

## C. 部分交接与物理异常（5 项）

| ID | 注入条件 | 期望结果 |
|---|---|---|
| H01 | 托盘抬升但叉臂承托比不足阈值 | 不转移货物所有权 |
| H02 | F02 已接触托盘但 F01 未完全卸载 | 不发生双重所有权提交；等待完整交接证据 |
| H03 | 托盘滑落后短暂接触货架 | 不将瞬态接触误判为成功入库 |
| H04 | 交接中资源租约过期 | 阻断后续提交，进入隔离/恢复 |
| H05 | 放货后托盘持续晃动未满足稳定时间 | 延迟提交直至稳定；超时进异常流程 |

承托判据拆三个独立量：旧支撑承载份额、新支撑承载份额、持续稳定时间。
机械交接中两车同时接触托盘是正常过渡态，不能只判 `contact == true`。

## D. 多车并发与恢复（3 项）

| ID | 注入条件 | 期望结果 |
|---|---|---|
| C01 | 两机器人持同一托盘旧版本任务并发提交 | 至多一条符合版本和预约的转移成功 |
| C02 | CP-SAT 计划后执行前目标货位被占 | 执行时重新验证世界状态，拒绝旧计划重新规划 |
| C03 | 交接中进程终止重启，原租约过期 | 重新观测、重新取得租约，不重放旧动作/旧证据 |

C02 是八车调度层关键集成测试：**调度可行性与执行可提交性必须分离**。

## 六项不变量（每个测试统一检查）

| # | 不变量 |
|---|---|
| I1 | 库存守恒（无凭空增减，出入库事件除外） |
| I2 | 唯一归属（部分交接允许物理共同承托但须明确中间状态） |
| I3 | 事务原子性（状态+事件+幂等记录同生共死） |
| I4 | 证据有效性（身份正确、未失效、版本匹配） |
| I5 | 幂等性（同命令重复提交不重复改变状态） |
| I6 | 可恢复性（未闭合操作重启后可识别、隔离、对账） |

审计记录 schema：`run_id / seed / command_id / fault_id / injection_point /
pre_state_hash / evidence_id / commit_outcome / post_state_hash /
invariant_results / recovery_result`。异常测试额外记录真值（仅 evaluator）、
系统可用观测、两者差异。

## 消融设计（防"安全但什么也不做"）

| 组 | 物理证据门控 | 原子事务 | 失败对账 |
|---|---|---|---|
| B0 直接完成回报 | 无 | 无 | 无 |
| B1 仅物理门控 | 有 | 无 | 无 |
| B2 门控+事务 | 有 | 有 | 无 |
| B3 完整方案 | 有 | 有 | 有 |

指标：Unsafe Commit Rate / False Rejection Rate / Atomicity Violation Rate /
Recovery Success Rate & Time / Task Completion & Throughput /
Ledger–Physical Divergence Duration。

主实验：分层随机种子 + 随机故障时机与组合，≥30 独立运行种子，配对场景，
按运行种子算置信区间。**零次观测到错误提交 ≠ 错误概率为零。**

## 集成契约（GPT 提醒）

CP-SAT 任务下发接口固定为带状态版本与资源租约的命令协议——调度器不得
直接写库存或占用状态。G1 审计采用三级裁决：PASS / CONDITIONAL PASS / BLOCK。
